## 1. CMSとは何か？

### 1.1 基本概念
**CMS = Content Management System（コンテンツ管理システム）**

**簡単な例え**：
- CMSは「デジタルの図書館管理システム」のようなもの
- 本（コンテンツ）を整理・管理・配布するためのシステム
- 司書（管理者）が本を簡単に追加・編集・削除できる

### 1.2 CMSが解決する問題

**従来の問題**：
```
ニュース記事を追加したい
↓
エンジニアにHTMLファイル作成を依頼
↓
コードを書いてもらう
↓
サーバーにアップロード
↓
公開（時間がかかる・エンジニア必須）
```

**CMSを使った場合**：
```
ニュース記事を追加したい
↓
管理画面にログイン
↓
記事を入力（Word感覚）
↓
「公開」ボタンをクリック
↓
即座に公開（簡単・誰でもできる）
```

### 1.3 CMSのメリット

| メリット | 説明 | 具体例 |
|----------|------|--------|
| **非技術者でも操作可能** | プログラミング知識不要 | 橋本さんや尾崎さんがニュース記事を自分で投稿 |
| **コンテンツ更新が簡単** | Word感覚で記事作成 | 展示会情報を即座に公開 |
| **一元管理** | すべてのコンテンツを一箇所で管理 | 商品情報・ニュース・お知らせを統合管理 |
| **権限管理** | ユーザーごとに編集権限を設定 | 橋本さん：全権限、尾崎さん：ニュースのみ |
| **バックアップ・履歴** | 過去の状態に戻すことが可能 | 間違って削除しても復元可能 |

## 2. CMSの種類と特徴

### 2.1 従来型CMS（Traditional CMS）

**特徴**：
- フロントエンド（表示部分）とバックエンド（管理部分）が一体化
- サーバーサイドでHTMLを生成
- 例：WordPress、Drupal

**メリット**：
- 設定が簡単
- プラグインが豊富
- 学習コストが低い

**デメリット**：
- 柔軟性が低い
- フロントエンドの自由度が制限
- セキュリティリスク

### 2.2 ヘッドレスCMS（Headless CMS）

**特徴**：
- バックエンド（管理部分）のみ提供
- フロントエンドは別途開発
- APIでデータをやり取り

**メリット**：
- フロントエンドの自由度が高い
- 複数チャネル対応（Web・アプリ・SNS）
- セキュリティが高い
- 高速表示

**デメリット**：
- 設定が複雑
- 開発コストが高い
- 技術的知識が必要

### 2.3 図解：従来型 vs ヘッドレス

```
【従来型CMS（WordPress等）】
┌─────────────────┐
│     フロントエンド      │ ← ユーザーが見る画面
│  （テーマ・デザイン）    │
├─────────────────┤
│     バックエンド       │ ← 管理画面・データベース
│   （管理・データ）      │
└─────────────────┘
    一体型システム

【ヘッドレスCMS】
┌─────────────────┐     ┌─────────────────┐
│   フロントエンド        │ API │     バックエンド       │
│   （Next.js等）        │<--->│   （CMS管理画面）      │
│   自由にデザイン可能     │     │   データのみ管理       │
└─────────────────┘     └─────────────────┘
      分離型システム
```

## 5. Next.js・FastAPIとの関係

### 5.1 アーキテクチャ図

```
【ZIGZAGLABシステム構成】

┌─────────────────┐    API    ┌─────────────────┐
│     Next.js           │ <------> │      CMS          │
│   (フロントエンド)      │   GET    │   (コンテンツ管理)   │
│                      │  POST    │                  │
│ ・商品一覧表示         │ PUT/DEL  │ ・記事管理         │
│ ・ニュース表示         │          │ ・商品管理         │
│ ・お問い合わせフォーム   │          │ ・画像管理         │
└─────────────────┘          └─────────────────┘
         ↑                            ↑
      ユーザー                     管理者
   (サイト閲覧)                  (コンテンツ更新)


【Future: Phase3でFastAPI追加】

┌─────────────────┐          ┌─────────────────┐
│     Next.js           │          │     FastAPI        │
│   (フロントエンド)      │ <------> │   (バックエンド)     │
└─────────────────┘          └─────────────────┘
         ↑                            ↑
         └─────────  CMS  ─────────────┘
                コンテンツデータ
```

### 5.2 データフローの例

**ニュース記事を表示する場合**：

```
1. ユーザーがニュースページを開く
   ↓
2. Next.jsがCMSにAPIリクエスト
   GET https://cms.zigzaglab.biz/api/news
   ↓
3. CMSがニュースデータをJSONで返す
   {
     "id": 1,
     "title": "推し活EXPO出展のお知らせ",
     "content": "9月24日-26日に...",
     "image": "https://...",
     "publishedAt": "2025-07-22"
   }
   ↓
4. Next.jsがデータを受け取り、HTMLに変換
   ↓
5. ユーザーに表示
```

### 5.3 技術的な連携方法

#### Next.jsでCMSデータを取得
```javascript
// pages/news/index.js
export async function getStaticProps() {
  // CMSからニュース一覧を取得
  const res = await fetch('https://cms.zigzaglab.biz/api/news');
  const news = await res.json();
  
  return {
    props: { news },
    revalidate: 60 // 60秒ごとに再生成
  };
}

function NewsPage({ news }) {
  return (
    <div>
      <h1>ニュース一覧</h1>
      {news.map(article => (
        <div key={article.id}>
          <h2>{article.title}</h2>
          <p>{article.content}</p>
        </div>
      ))}
    </div>
  );
}
```

#### CMSの設定例（Strapi）
```javascript
// config/api.js
module.exports = {
  rest: {
    defaultLimit: 25,
    maxLimit: 100,
  },
  settings: {
    cors: {
      enabled: true,
      origin: ['https://zigzaglab.biz', 'http://localhost:3000']
    }
  }
};
```

- **それぞれが専門分野に特化した効率的な構成**

### 7.8 まとめ

**CMS使用のメリット：**
- 開発速度が圧倒的に早い
- 運用が安定している
- 非技術者でも使いやすい
- コストが安い

**自作システムのメリット：**
- 完全にカスタマイズ可能
- 独自要件に対応可能
- データ構造を自由に設計

**ZIGZAGLABの場合：**
Phase2では**CMS使用**が最適解。Phase3でECサイト機能のみ自作システムを追加する段階的アプローチが推奨。
